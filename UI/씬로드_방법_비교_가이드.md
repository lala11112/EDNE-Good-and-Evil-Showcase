# 씬 로드 방법 비교 - 어떤 게 제일 좋을까?

## 🤔 질문: "Inspector에서 등록하는 게 더 나은 거 아니야?"

**답변: 상황에 따라 다르지만, Enum 기반 하이브리드가 최선입니다!** ⭐

---

## 📊 3가지 방법 완전 비교

### 방법 1: 전용 메서드 (기존)

```csharp
// UIManager.cs
public void LoadGameplayScene()
{
    SceneManager.LoadScene("Level_01_Gameplay");
}

// 사용
UIManager.Instance.LoadGameplayScene();
```

### 방법 2: 문자열 + Inspector (일반화)

```csharp
// UIManager.cs
public void LoadScene(string sceneName)
{
    SceneManager.LoadScene(sceneName);
}

// Inspector
[SerializeField] private string targetScene = "Level_01_Gameplay";

// 사용
UIManager.Instance.LoadScene(targetScene);
```

### 방법 3: Enum + Inspector ⭐ 추천!

```csharp
// SceneLoader.cs
public enum GameScene { Title, Level_01_Gameplay }

[SerializeField] private GameScene targetScene;

// 사용
UIManager.Instance.LoadScene(targetScene);
```

## 🎯 실전 시나리오 비교

### 시나리오 1: 씬 이름을 Level_01 → Stage_01로 변경

#### 방법 1 (전용 메서드)
```
1. UIManager.cs 수정:
   LoadGameplayScene() 내부 문자열 변경

✅ 장점:
   - 한 곳만 수정
   - 컴파일 에러로 체크
   
❌ 단점:
   - 코드 수정 필요
```

#### 방법 2 (문자열)
```
1. 모든 GameObject의 Inspector 확인
2. targetScene 문자열 수동 변경
3. 하나라도 놓치면 런타임 에러

✅ 장점:
   - 없음
   
❌ 단점:
   - 모든 프리팹/GameObject 수동 확인
   - 놓치기 쉬움 ⚠️
   - 런타임에만 발견
```

#### 방법 3 (Enum) ⭐
```
1. GameScene enum 수정:
   Level_01_Gameplay → Stage_01_Gameplay

✅ 장점:
   - 한 곳만 수정
   - 컴파일 에러로 모든 사용처 체크
   - Inspector 자동 업데이트
   
❌ 단점:
   - 없음!
```

**승자: 방법 3 (Enum)** ✅

```csharp
// ✅ 자동완성으로 선택만 하면 됨
```

**승자: 방법 3 (Enum)** ✅

### 시나리오 3: 10개의 레벨 추가

#### 방법 1
```csharp
// UIManager.cs에 10개 메서드 추가
public void LoadLevel1() { ... }
public void LoadLevel2() { ... }
// ...
public void LoadLevel10() { ... }

// 각 버튼마다 다른 메서드 호출
```
**단점:** 보일러플레이트 코드 10개 ❌

#### 방법 2
```
// Inspector에서 각 버튼마다 문자열 입력
Level_01_Gameplay
Level_02_Gameplay
...
Level_10_Gameplay
```
**단점:** 오타 가능성 10배 증가 ⚠️

#### 방법 3
```csharp
// GameScene enum에만 추가
public enum GameScene
{
    Title,
    Level_01_Gameplay,
    Level_02_Gameplay,
    // ... Level_03 ~ Level_09
    Level_10_Gameplay
}

// Inspector에서 드롭다운 선택만!
```
**장점:** 타입 안전 + 간편함 ✅

**승자: 방법 3 (Enum)** ✅

```
"Level_02_Gameplay" vs "Level_2_Gameplay" vs "Level02_Gameplay"
```
**단점:** 오타 위험 ⚠️

#### 방법 3
```
디자이너가 Inspector 드롭다운에서 선택
- Title
- Level_01_Gameplay
- Level_02_Gameplay ← 클릭!
- Level_03_Gameplay
```
**장점:** 오타 불가능 + 독립적 작업 ✅

**승자: 방법 3 (Enum)** ✅

## 💻 코드 예시

### 방법 3 (Enum) 사용법

#### 1. Enum 정의 (한 번만)
```csharp
// SceneLoader.cs
public enum GameScene
{
    Title,
    Level_01_Gameplay,
    Level_02_Gameplay,
    GameOver
}
```

#### 2. UIManager에서 사용
```csharp
// UIManager.cs
public void LoadScene(GameScene scene)
{
    string sceneName = scene.ToString();
    SceneManager.LoadScene(sceneName);
}

// 편의 메서드도 유지 가능
public void LoadGameplayScene()
{
    LoadScene(GameScene.Level_01_Gameplay);
}
```

#### 3. TitleUIController에서 사용
```csharp
// 방법 A: 코드에서 직접
void OnGameStartClicked()
{
    UIManager.Instance.LoadScene(GameScene.Level_01_Gameplay);
}

// 방법 B: Inspector에서 설정
[SerializeField] private GameScene targetScene;

void OnButtonClicked()
{
    UIManager.Instance.LoadScene(targetScene);
}
```

```csharp
// 버튼에 SceneLoader 컴포넌트 추가
```

## 🎯 **최종 답변**

### Q: "Inspector에서 등록하는 게 더 나은 거 아니야?"

**A: 네, 맞습니다! 하지만 문자열이 아닌 Enum을 사용하세요!**

### 왜 Enum이 최선인가?

```
문자열의 장점 (유연성) + 전용 메서드의 장점 (타입 안전)
= Enum 기반 방식 ⭐
```

### 실제 비교

```csharp
// ❌ 방법 2: 문자열 (비추천)
[SerializeField] private string sceneName = "Level_01_Gameplay";
// 문제: 오타, 존재하지 않는 씬, 리팩토링 어려움

// ✅ 방법 3: Enum (추천!)
[SerializeField] private GameScene scene = GameScene.Level_01_Gameplay;
// 장점: 오타 불가, 자동완성, 타입 안전, 리팩토링 쉬움
```

## ✅ 체크리스트

### Enum 방식을 사용해야 하는 이유

- [x] 타입 안전성 (컴파일 타임 체크)
- [x] 오타 방지 (Enum은 오타 불가능)
- [x] IDE 자동완성 (생산성 향상)
- [x] Inspector 드롭다운 (디자이너 친화)
- [x] 리팩토링 용이 (Find & Replace)
- [x] 런타임 에러 최소화
- [x] 유지보수 쉬움
- [x] 확장 간편 (Enum에만 추가)

### 문자열 방식의 문제점

- [ ] 오타 가능
- [ ] 존재하지 않는 씬 참조 가능
- [ ] IDE 자동완성 안 됨
- [ ] 리팩토링 어려움
- [ ] 런타임 에러 많음
- [ ] 디버깅 어려움
